# وب‌سایت احسان احترامی

وب‌اپ فارسی و راست‌به‌چپ برای معرفی، نمونه‌کار، خدمات، آموزش و دریافت درخواست مشاوره. این پروژه با Next.js، TypeScript و Tailwind CSS ساخته شده است. طرح بصری بر پایه رنگ ذغالی، طلایی شامپاینی، بنفش و فونت محلی Vazirmatn است.

## راه‌اندازی سریع

Node.js نسخه ۲۲٫۱۳ یا جدیدتر لازم است؛ آزمون این تحویل روی Node.js 24 انجام شده است.

```bash
npm ci
npm run setup
npm run db:init
npm run dev
```

نشانی: `http://127.0.0.1:3000`. دستور setup فقط در نبود `.env.local` آن را می‌سازد و یک کلید تصادفی محلی تولید می‌کند. هیچ کلید واقعی در نسخه منبع و ZIP قرار ندارد.

برای اجرای خروجی Production روی رایانه:

```bash
npm run build
npm start
```

در صورت استفاده از پورت یا hostname متفاوت، `NEXT_PUBLIC_SITE_URL` را مطابق نشانی مرورگر تغییر دهید؛ بررسی مبدأ درخواست عمداً دقیق است. برای توسعه و Production هم‌زمان از یک پوشه `.next` استفاده نکنید؛ سرور توسعه را ببندید یا checkout جدا داشته باشید.

## معماری صفحات و Design System

| مسیر                  | کاربرد                                                  |
| --------------------- | ------------------------------------------------------- |
| `/`                   | معرفی سینمایی، آثار منتخب، خدمات، درباره و مسیر همکاری  |
| `/portfolio`          | گالری Masonry، فیلتر، لایت‌باکس، ویدیو و مقایسه قبل/بعد |
| `/services`           | همه خدمات                                               |
| `/services/[slug]`    | ۱۱ صفحه مستقل برای سئوی خدمات                           |
| `/pricing`            | ۱۰ دسته تعرفه، سه سطح همکاری و درخواست برآورد           |
| `/education`          | هفت برنامه آموزشی قابل‌ویرایش                           |
| `/about`              | معرفی و سابقه؛ نظرات فقط در صورت ثبت نظر واقعی          |
| `/faq`                | پاسخ‌های کوتاه و Schema سؤال‌های متداول                 |
| `/contact`            | فرم دو مرحله‌ای و تماس مستقیم                           |
| `/privacy` و `/terms` | اطلاعات حریم خصوصی و شرایط اولیه همکاری                 |
| `/api/consultation`   | مسیر سروری خصوصی برای ثبت فرم                           |

مسیر اصلی: دیدن آثار ← انتخاب خدمت ← بررسی تعرفه یا مشاوره ← ثبت درخواست یا تماس.

رنگ‌ها، فاصله‌ها و breakpoints در `app/globals.css` متمرکزند. عرض محتوا حداکثر ۱۲۸۰ پیکسل، پنل‌ها با گوشه‌های ۹ تا ۲۰ پیکسل و شیشه محدود طراحی شده‌اند. فونت از بسته محلی بارگذاری می‌شود و به Google Fonts وابسته نیست. انیمیشن و پارالاکس ملایم با Reduce Motion غیرفعال می‌شوند. موبایل نوار تماس ثابت و منوی تمام‌صفحه دارد.

## ویرایش محتوا

فایل اصلی: `lib/content.ts`.

- `site`: نام، معرفی، تلفن، شبکه‌های اجتماعی، شهر و محدوده فعالیت، پرتره، ویدیوی Hero و PDF.
- `services`: خدمات، توضیح، تصویر و مسیر صفحه.
- `works`: آثار، دسته، alt، ابعاد، توضیح و منتخب‌بودن.
- `pricingCategories` و `plans`: تعرفه‌ها؛ هیچ مبلغ ساختگی درج نشده است.
- `courses`: سطح، شیوه برگزاری، سرفصل و مدت دوره‌ها.
- `faqs`: منبع مشترک FAQ و دستیار محلی.
- `testimonials`: فعلاً خالی؛ با افزودن نظر واقعی، بخش آن در صفحه درباره ظاهر می‌شود.

شهر عمداً خالی است. پس از تعیین آن، `site.city` و `site.serviceArea` را کامل کنید. در JSON-LD فقط اطلاعات معلوم درج می‌شود. از `Person` با عنوان حرفه‌ای عکاس، `ProfessionalService` (زیرنوع LocalBusiness)، `Service` و `FAQPage` استفاده شده است؛ نوع ساختگی `Photographer` به Schema اضافه نشده است.

### تعویض عکس‌ها و ویدیو

تصاویر بهینه‌شده در `public/images` هستند. فایل اصلی WebP را جایگزین یا اضافه کنید و مشخصات را در `works` ثبت کنید. نام فایل‌ها را لاتین کوچک و با خط تیره انتخاب کنید. ابعاد واقعی را وارد کنید تا چیدمان نپرد. دستور build به‌صورت خودکار نسخه‌های ۳۲۰، ۶۴۰، ۹۶۰، ۱۴۴۰ و ۱۹۲۰ پیکسلی می‌سازد. برای دیدن آن‌ها در توسعه پس از افزودن عکس، اجرا کنید:

```bash
node scripts/build-thumbnails.mjs
```

این روش بدون هزینه Cloudflare Images، thumbnail و srcset ایجاد می‌کند. Lightbox از اندازه بزرگ‌تر استفاده می‌کند. فایل‌های ارسالی کاربر در این نسخه استفاده شده‌اند و هیچ مشتری، جایزه یا نظر جدیدی جعل نشده است. دسته‌های فاقد نمونه، پیام صریح خالی دارند. نام پروژه‌ها توصیفی است و نسبت همکاری تجاری با برندهای داخل تصاویر ادعا نمی‌کند.

برای ویدیو، یک MP4 دارای مجوز در `public/videos` قرار دهید و فیلد `video` اثر را تنظیم کنید. تصویر `image` پوستر آن است. برای Hero، `site.heroVideo` را به مسیر ویدیو تغییر دهید؛ توقف/پخش و رعایت Reduce Motion پشتیبانی می‌شود.

برای قبل/بعد، یک اثر با دسته `قبل و بعد ادیت` و مسیرهای `before` و `after` واقعی اضافه کنید. دو تصویر باید کادر و ابعاد یکسان داشته باشند. رابط مقایسه با ماوس، لمس و صفحه‌کلید کار می‌کند. در فایل‌های تحویلی جفت معتبر قبل/بعد و ویدیو وجود نداشت؛ چنین اثری ساخته یا جعل نشده است.

`public/tariffs.pdf` راهنمای فعلی است؛ برای تغییر PDF، فایل را جایگزین یا `site.tariffPdf` را عوض کنید. پس از تغییر تعرفه‌ها، PDF را نیز به‌روز کنید.

## فرم، ذخیره‌سازی و امنیت

فرم پس از ذخیره واقعی، پاسخ موفق و کد تصادفی `EH-…` دریافت می‌کند. اطلاعات فرم عمومی نیست و در localStorage ذخیره نمی‌شود. ارسال مجدد همان درخواست با کلید idempotency، رکورد دوم ایجاد نمی‌کند. انتخاب اینستاگرام به شناسه حساب نیاز دارد. فایل مرجع از طریق لینک ارائه می‌شود؛ آپلود فایل اجرایی در این نسخه وجود ندارد.

محافظت‌ها: اعتبارسنجی مشترک Zod روی سرور و مرورگر، تبدیل ارقام فارسی/عربی، تأیید رضایت، honeypot، بررسی Origin، سقف بدنه ۱۶ کیلوبایت، rate limit پایدار، کوئری پارامتری و نبود کلید در Frontend. پاسخ موفق نمایشی وجود ندارد؛ نبود تنظیمات یا خطای پایگاه داده، پیام خطای قابل‌فهم و راه تماس نشان می‌دهد.

- محلی: SQLite در `.data/leads.sqlite`، خارج از public و Git.
- آنلاین: Neon Postgres از طریق HTTP؛ با محیط Serverless سازگار است.
- محدودیت اتصال: ۱۰ تلاش در ۱۵ دقیقه؛ شماره: ۳ تلاش در ساعت. شناسه‌ها با HMAC نگهداری می‌شوند.
- IP فقط پشت پراکسی مورداعتماد Vercel یا Cloudflare خوانده می‌شود. روی میزبان دیگر، سازگاری پراکسی را پیش از فعال‌کردن `TRUST_PROXY` بررسی کنید.
- نگهداری درخواست‌ها ۱۸۰ روز است. پاک‌سازی هنگام ثبت درخواست جدید انجام می‌شود؛ برای مهلت حذف دقیق بدون ترافیک، یک کار زمان‌بندی‌شده در پایگاه داده لازم است.
- هیچ پیامک، ایمیل یا پیام واتس‌اپ خودکاری ارسال نمی‌شود. برای بررسی درخواست‌ها از کنسول خصوصی Neon استفاده کنید؛ دکمه واتس‌اپ در اختیار بازدیدکننده است.

مشاهده رکوردها فقط در کنسول احرازشده پایگاه داده:

```sql
SELECT id, created_at, payload FROM leads ORDER BY created_at DESC LIMIT 50;
```

برای حذف درخواست، پس از تطبیق هویت درخواست‌کننده، رکورد مربوط به کد پیگیری را در همان کنسول حذف کنید. دسترسی عمومی خواندن جدول ندهید. این نسخه پنل مدیریت ندارد.

## متغیرهای محیطی

| نام                    | مقدار یا کاربرد                                                             |
| ---------------------- | --------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL` | origin کامل HTTPS دامنه نهایی، بدون مسیر اضافی؛ هنگام build و runtime یکسان |
| `STORAGE_DRIVER`       | `local` برای رایانه، `neon` برای انتشار                                     |
| `DATABASE_URL`         | رشته اتصال Neon؛ فقط Secret سمت سرور                                        |
| `RATE_LIMIT_SECRET`    | حداقل ۳۲ کاراکتر تصادفی؛ فقط Secret سمت سرور                                |
| `TRUST_PROXY`          | `true` فقط برای استقرار مستقیم پشت پراکسی پشتیبانی‌شده                      |
| `HOSTING_PLATFORM`     | برای Cloudflare برابر `cloudflare`؛ در Vercel خالی                          |

تولید کلید توسط خود مدیر در ترمینال شخصی:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

کلید را در داشبورد میزبان ذخیره کنید، نه در GitHub، فایل عمومی یا پیام پشتیبانی. `.env.example` فقط نام و نمونه تنظیمات را دارد. `.env.local` محلی را به میزبان آپلود نکنید.

## انتشار در GitHub

در حساب خود یک Repository خالی با نام دلخواه مانند `ehsan-portfolio` بسازید. پوشه پروژه را به‌عنوان ریشه Repository استفاده کنید:

```bash
git init
git add .
git commit -m "feat: launch Persian photography portfolio"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/ehsan-portfolio.git
git push -u origin main
```

اگر Git قبلاً در پوشه تنظیم شده است، مرحله init و افزودن origin را تکرار نکنید. پیش از push با `git status` مطمئن شوید `.env.local`، `.data`، node_modules و خروجی‌های build وارد Git نشده‌اند.

ساختار پیشنهادی commit: `feat:` قابلیت، `fix:` رفع اشکال، `content:` محتوا و عکس، `style:` ظاهر، `docs:` راهنما و `test:` آزمون.

## انتشار روی Vercel

1. حساب GitHub را در Vercel متصل و Repository را Import کنید. Framework برابر Next.js و Build Command برابر `npm run build` باشد.
2. یک پایگاه Neon از حساب خود یا Marketplace ایجاد کنید و رشته اتصال آن را در `DATABASE_URL` قرار دهید.
3. `STORAGE_DRIVER=neon`، `RATE_LIMIT_SECRET`، `TRUST_PROXY=true` و `NEXT_PUBLIC_SITE_URL` را برای محیط Production تنظیم کنید. متغیرهای Secret نباید با `NEXT_PUBLIC_` شروع شوند.
4. با تنظیمات اتصال Neon در محیط خصوصی محلی، `npm run db:init` را یک‌بار اجرا کنید؛ این دستور فقط جدول‌ها را در صورت نبودن ایجاد می‌کند.
5. Deploy کنید. اگر دامنه اولیه بعد از اولین deploy تعیین شد، origin را به‌روز کنید و یک redeploy انجام دهید.
6. یک فرم آزمایشی در دامنه نهایی ثبت کنید و وجود رکورد را در Neon کنترل کنید. URLهای Preview برای فرم باید origin همان Preview را داشته باشند.
7. برای دامنه اختصاصی، در Project Settings بخش Domains، دامنه را اضافه و DNS اعلام‌شده توسط Vercel را تنظیم کنید. سپس origin را تغییر داده و redeploy کنید.

**رایگان‌بودن Vercel برای این سایت تضمین نمی‌شود:** پلن Hobby مخصوص استفاده شخصی غیرتجاری است. چون هدف این سایت جذب مشتری خدمات است، پیش از انتخاب پلن شرایط حساب را بررسی کنید. هیچ پلن پولی از طرف شما خریداری نشده است. منابع: [Vercel Hobby](https://vercel.com/docs/plans/hobby)، [اتصال Postgres](https://vercel.com/docs/postgres).

## مسیر Cloudflare با امکان استفاده از سهمیه رایگان

نسخه دارای فرم سروری باید روی **Workers** اجرا شود؛ Cloudflare Pages صرفاً استاتیک و GitHub Pages به‌تنهایی مسیر API این پروژه را اجرا نمی‌کنند. پیکربندی OpenNext و Wrangler در پروژه موجود است. این مسیر با سهمیه‌های رایگان Workers و Neon قابل بررسی است؛ ظرفیت و شرایط پلن‌ها را در زمان انتشار کنترل کنید.

1. Repository را در Cloudflare Workers Builds به حساب خود متصل کنید.
2. نام Worker را در `wrangler.jsonc` و `WORKER_SELF_REFERENCE` یکسان نگه دارید. نام پیش‌فرض `ehsan-ehterami` است و در حساب شما باید آزاد باشد.
3. `NEXT_PUBLIC_SITE_URL` را برای build و runtime به URL واقعی Worker یا دامنه اختصاصی تنظیم کنید. در تنظیمات runtime، `STORAGE_DRIVER=neon`، `HOSTING_PLATFORM=cloudflare` و `TRUST_PROXY=true` قرار دارند.
4. `DATABASE_URL` و `RATE_LIMIT_SECRET` را به‌عنوان Secret در داشبورد Worker ثبت کنید. جدول‌های Neon را با `npm run db:init` ایجاد کنید.
5. Build Command: `npm run build:cloudflare`. Deploy Command: `npm run deploy:cloudflare`.
6. پس از Deploy، فرم، تصاویر و canonical را روی دامنه واقعی بررسی کنید. قابلیت ذخیره‌سازی ابری بدون حساب و Secretهای خودتان فعال نمی‌شود.
7. دامنه اختصاصی را در Settings → Domains & Routes اضافه کنید و origin را نیز به‌روز کنید.

برای اجرای فرمان‌ها در حساب خود:

```bash
npm run build:cloudflare
npm run preview:cloudflare
npm run deploy:cloudflare
```

در Windows، پشتیبانی کامل ابزار OpenNext تضمین نشده است؛ اگر build محلی دچار خطای symlink یا محیط شد، همان commit را در Workers Builds یا محیط Linux اجرا کنید. هیچ R2، Cloudflare Images یا سرویس پولی الزامی به این پروژه اضافه نشده است؛ تصاویر در زمان build بهینه می‌شوند.

منابع: [راهنمای OpenNext](https://opennext.js.org/cloudflare/get-started)، [قیمت‌گذاری Workers](https://developers.cloudflare.com/workers/platform/pricing/)، [راهنمای فعلی Next.js در Cloudflare](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/).

## سئو، نصب و کارایی

برای هر صفحه title، description و canonical اختصاصی وجود دارد. Open Graph متنی، sitemap، robots، Schema خدمات و FAQ و alt فارسی تنظیم شده‌اند. دامنه نهایی باید پیش از انتشار در env تعیین شود. شهر یا آدرس ساختگی درج نشده است. PWA شامل manifest، آیکون و صفحه fallback آفلاین است؛ ثبت فرم در حالت آفلاین انجام نمی‌شود. نمایش دکمه نصب به مرورگر بستگی دارد.

قالب تصاویر WebP، ابعاد رزروشده، بارگذاری تنبل، فونت محلی، تصاویر چنداندازه‌ای و انیمیشن‌های سبک استفاده شده‌اند. امتیاز Core Web Vitals به هاست، شبکه و کاربران واقعی وابسته است؛ باید پس از انتشار با PageSpeed Insights و Search Console سنجیده شود. نتیجه آزمون محلی جایگزین داده میدانی نیست.

## دستیار و توسعه آینده

`lib/assistant.ts` منطق بدون هزینه API را پیاده می‌کند و `faqs` پایگاه پاسخ است. گفت‌وگو در حافظه صفحه می‌ماند. برای افزودن مدل هوشمند، یک Route Handler سروری جدید بسازید، کلید را در env محرمانه قرار دهید و همان کنترل Origin، محدودسازی، حد طول ورودی و سیاست عدم حدس را حفظ کنید. این نسخه به مدل خارجی متصل نیست.

تعریف داده‌های سایت از UI جدا است و بعداً می‌تواند از CMS خوانده شود. گالری در مرورگرهای پشتیبان WebMCP ابزار `filter_portfolio` را ارائه می‌کند؛ مرورگرهای دیگر همان رابط معمول را دارند.

## آزمون و بررسی

```bash
npm run typecheck
npm test
npm run build
npm start
# در ترمینال دیگر، فقط روی محیط آزمایشی:
npm run test:smoke
```

آزمون smoke درخواست آزمایشی در پایگاه محلی می‌نویسد؛ آن را بدون آگاهی روی Production اجرا نکنید. نتیجه تحویل در `QA.md` ثبت شده است. برای ادامه بررسی دستی: منوی موبایل، فیلتر گالری، Escape و پیکان‌ها در Lightbox، فرم با ارقام فارسی، رضایت تماس، پاسخ نامشخص دستیار، PDF، صفحات ۴۰۴ و صفحه آفلاین را بررسی کنید.

## پیش‌نمایش GitHub Pages

دستور `npm run build:pages` خروجی ایستا را در `.next-pages/` می‌سازد. مسیر پایه با `NEXT_PUBLIC_BASE_PATH` و نشانی کامل با `NEXT_PUBLIC_SITE_URL` تعیین می‌شود. پیش‌فرض مخزن `ehsanersan/ehsan-portfolio` است.

در این نسخه، فرم پس از اعتبارسنجی پیام واتس‌اپ آماده می‌کند و هیچ ذخیرهٔ سروری یا کد پیگیری ساختگی ندارد. API اصلی در کد حفظ شده و برای ساخت ایستا موقتاً کنار گذاشته و سپس بازیابی می‌شود. سرویس‌ورکر در نسخهٔ Pages فعال نیست. گالری، فیلترها، لایت‌باکس، صفحات خدمات، PDF و دستیار محلی فعال‌اند. تنظیمات هدر سرور روی Pages اعمال نمی‌شوند.

برای انتشار: Settings → Pages → Source: GitHub Actions. گردش‌کار `.github/workflows/pages.yml` با هر Push به `main` آزمون و ساخت را اجرا و منتشر می‌کند. مرحلهٔ بازکردن `source-upload.zip` فقط برای انتقال اولیه از رابط مرورگر است؛ پس از اجرای نخست، کد کامل به مخزن Commit می‌شود و ZIP از شاخهٔ جاری حذف می‌شود.
